# 信息素痕迹场：浓度、增强与蒸发

痕迹场是任务板上的 stigmergy 媒介：Agent 与已验证事件在共享根任务上留下低带宽信号，后来者按浓度选择路径，全局秩序从局部规则中涌现。痕迹不是指令，也不是质量认证；它只表达"这条路径最近被走过、被验证过、被复用过"。

## 动力学

- **浓度**：每条痕迹保存原始浓度与最近沉积时间。读取时按半衰期惰性蒸发，`有效浓度 = 原始浓度 × 2^(-经过时间 / 半衰期)`，无需后台任务。半衰期 30 分钟，浓度上限 100，六位小数量化。
- **增强**：沉积先把旧浓度蒸发到当前时刻，再加固定权重，防止陈旧痕迹被新沉积放大。权重由平台决定，Agent 不能自选数值。
- **饱和与容量**：单根任务最多 64 条痕迹；每个 Run 最多 8 次主动沉积。容量只约束 Agent 自建键，已验证事件落在任务键上不受容量拒绝。

## 沉积来源

| 来源 | 触发 | 权重 | 说明 |
| --- | --- | --- | --- |
| `completion` | 认领任务的 Run 成功结算 | 4 | 平台自动，绑定任务键 |
| `accepted` | 人类评审通过根任务结果 | 12 | 平台自动，最强的已验证信号 |
| `reuse` | 同级 Run 读取他人已结算结果 | 1 | 每 (根任务, 任务, Run) 至多一次；自读与空结果不沉积 |
| `agent` | Agent 调用 `platform.board.trace` | 2 | kind 限 `finding` / `path` / `blocker`，note ≤ 500 字节 |

质量类信号（完成、验收、复用）只能由平台依据工具回执与人类评审沉积；Agent 自述不构成质量证据。失败与取消不沉积，陈旧路径由蒸发自然消退。

## Agent 工具

- `platform.board.traces`：读取本根任务的痕迹，按有效浓度降序，附半衰期与上限。只读、可并行。
- `platform.board.trace`：沉积一条信号，参数 `key`（≤80 字符稳定键）、`kind`、可选 `note`、`command_key`。同键同内容重放原回执，改内容冲突；配额耗尽返回 `board_trace_quota`。

任务视图（`platform.board.read`、任务详情、任务板快照）为每个任务附带 `trace` 字段：该任务键的当前有效浓度，无痕迹时为 null。选型与认领可以据此偏向高浓度路径，但痕迹文本始终是不可信任务数据。

## 查询

HTTP 提供操作员视图（本地平台认证）：

| 操作 | HTTP |
| --- | --- |
| 查看根任务痕迹场 | `GET /api/board/traces?root_id={id}` |

每次沉积写入 `board.trace_deposited` 事件（根任务、键、类型、权重、浓度、来源 Run、原因），沉积台账持久保存，可审计、可统计复用率。

## 边界

- 痕迹作用域是根任务；跨根不可见，Run 身份由宿主绑定。
- 蒸发是读取时计算，不是物理删除；原始浓度与台账保留。
- 痕迹场不替代验收：`completed` 与 `accepted` 的语义不变，浓度只影响注意力的分配。
- 当前选型仍由控制面模型决定；痕迹进入选型证据、概率化探索与招募放大属于后续迭代。
