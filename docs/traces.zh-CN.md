# 信息素痕迹场：浓度、增强与蒸发

痕迹场是任务板上的 stigmergy 媒介：Agent 与已验证事件在共享根任务上留下低带宽信号，后来者按浓度选择路径，全局秩序从局部规则中涌现。痕迹不是指令，也不是质量认证；它只表达"这条路径最近被走过、被验证过、被复用过"。

## 动力学

- **浓度**：每条痕迹保存原始浓度与最近沉积时间。读取时按半衰期惰性蒸发，`有效浓度 = 原始浓度 × 2^(-经过时间 / 半衰期)`，无需后台任务。半衰期与浓度上限可在研究者视图调整（默认 30 分钟、上限 100），六位小数量化。
- **增强**：沉积先把旧浓度蒸发到当前时刻，再加固定权重，防止陈旧痕迹被新沉积放大。权重由平台决定，Agent 不能自选数值。
- **饱和与容量**：单根任务最多 64 条痕迹；每个 Run 最多 8 次主动沉积。容量只约束 Agent 自建键，已验证事件落在任务键上不受容量拒绝。

## 沉积来源

| 来源 | 触发 | 权重 | 说明 |
| --- | --- | --- | --- |
| `completion` | 认领任务的 Run 成功结算 | 4 | 平台自动，绑定任务键 |
| `accepted` | 人类评审通过根任务结果 | 12 | 平台自动，最强的已验证信号 |
| `reuse` | 同级 Run 读取他人已结算结果 | 1 | 每 (根任务, 任务, Run) 至多一次；自读与空结果不沉积 |
| `recruitment` | 成功 Run 放大其留下的 Agent 信号 | 2 | 招募放大：每 (痕迹, Run) 至多一次；失败 Run 不招募 |
| `failure` | 确定失败的 Run 结算 | -4 | 负反馈：路径降权至 0；结果未知（interrupted）不惩罚 |
| `agent` | Agent 调用 `platform.board.trace` | 2 | kind 限 `finding` / `path` / `blocker`，note ≤ 500 字节 |

质量类信号（完成、验收、复用）只能由平台依据工具回执与人类评审沉积；Agent 自述不构成质量证据。取消不沉积；确定失败施加负反馈降权，陈旧路径由蒸发自然消退。招募把成功与路径信号耦合：只有真正做成工作的 Run，才能把它指出的路径放大给同伴。

## 个体损失鲁棒性

确定失败的任务在重试预算内（默认 2 次）自动回到待认领池，由控制面重新选型、新实例接手；预算耗尽才结算 failed 并阻塞上游。被邀请但从未认领的任务同样有界重排。结果未知（interrupted）的 Run 既不惩罚也不自动重试——外部效果未证实，须走恢复/对账，不能静默重放。失败降权与有界重试共同构成负反馈：群体绕开死路、损失个体后仍收敛。

## 供给顺序与选型证据

- **痕迹加权供给 + 拥挤规避**：任务刺激 = 有效浓度 / (1 + 同根活跃工作者数)。控制面按刺激降序供给待处理任务，同刺激按发布时间 FIFO；拥挤分支的刺激被稀释，工作者自然分散到其它分支。设置 `ANT3_BOARD_EXPLORATION=1` 启用探索模式：按 `刺激 + 1` 的概率无放回抽样（splitmix64 种子化），新任务保有底部概率，防止路径锁死。默认确定性，便于回归。
- **选型证据**：路由把根任务最强的 8 条痕迹（键、类型、浓度、稀释后刺激）与当前拥挤数作为不可信证据传入选型模型；能力匹配优先，痕迹只作倾向参考，不授予任何权限。

## Agent 工具

- `platform.board.traces`：读取本根任务的痕迹，按有效浓度降序，附半衰期与上限。**局部感知**：默认只返回浓度 ≥ 感知阈值（默认 1.0）的痕迹，弱痕迹存在但低于注意阈值（`below_threshold` 计数提示）；传 `min_strength: 0` 显式全览。只读、可并行。
- `platform.board.trace`：沉积一条信号，参数 `key`（≤80 字符稳定键）、`kind`、可选 `note`、`command_key`。同键同内容重放原回执，改内容冲突；配额耗尽返回 `board_trace_quota`。

任务视图（`platform.board.read`、任务详情、任务板快照）为每个任务附带 `trace` 字段：该任务键的当前有效浓度，无痕迹时为 null。选型与认领可以据此偏向高浓度路径，但痕迹文本始终是不可信任务数据。

## 查询

HTTP 提供操作员视图（本地平台认证）：

| 操作 | HTTP |
| --- | --- |
| 查看根任务痕迹场 | `GET /api/board/traces?root_id={id}` |

每次沉积写入 `board.trace_deposited` 事件（根任务、键、类型、权重、浓度、来源 Run、原因），沉积台账持久保存，可审计、可统计复用率。

## 根任务黑板与冲突裁决

Agent 用 `platform.board.note` 在根黑板上以稳定键发布发现：CAS 修订（读到几就传几，0 新建），引用最多 8 个痕迹键作为证据支持，支持度=引用痕迹的实时浓度和。冲突写入不先到先得，而是按证据强度裁决：更强支持取代在位者；更弱或平局（相对容差 1e-4，防蒸发抖动翻转裁决）保留在位者，新声明记为 superseded 历史。每次裁决发 `board.note_adjudicated` 事件（胜/负修订、双方分数、规则）。`platform.board.notes` 读活跃发现与裁决历史；操作员视图 `GET /api/board/tasks/{id}/notes`。黑板是 stigmergy 的"事实层"：痕迹给浓度，黑板给可裁决的内容。

## 振荡抑制

返工链（连续 changes_requested）按指数冷却：15s × 2^(链长-1)，上限 120s；冷却期内任务不进入供给与选型。链长上限 4：超限的退回被拒绝（rework_chain_exhausted），任务留在完成态交回人类评审；验收通过清零链。防止执行者↔验证者无限振荡消耗能量。

## 响应阈值分工

Preset（Preset 版本）积累执行经验：成功降低响应阈值（×1/1.25），确定失败升高（×1.25），夹在 [0.05, 0.95]，基线 0.5；结果未知与取消不计入经验。阈值越低，对弱刺激越敏感——专家 Preset 响应淡痕迹，新手只追强痕迹，分工从局部经验中涌现。响应概率采用经典阈值模型 s²/(s²+θ²)。经验统计（successes/failures/response_threshold）随能力目录进入选型证据，操作员可经 `GET /api/presets/experience` 查看。阈值是证据不是权威：选型仍由模型按能力匹配决定。

## 边界

- 痕迹作用域是根任务；跨根不可见，Run 身份由宿主绑定。
- 蒸发是读取时计算，不是物理删除；原始浓度与台账保留。
- 痕迹场不替代验收：`completed` 与 `accepted` 的语义不变，浓度只影响注意力的分配。
- 局部感知按浓度阈值过滤痕迹；同一个根任务下的任务清单本身仍可见，阈值与半衰期由操作员配置。
