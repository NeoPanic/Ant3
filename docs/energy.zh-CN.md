# 预算即能量：群体选择压力

能量把预算从会计治理变成涌现机制：把能量高效转化为验收成果的策略存活，浪费的策略饿死淘汰。

## 动力学

- **根能量池**：发布根任务可配 `energy_budget`（2000–10000000，默认 100000）。子任务共享根池。
- **预留**：每次派发（执行或审计 Run）原子预留 2000；可用能量不足即拒绝派发。
- **结算**：Run 结束释放预留并按真实 usage 计费——10 token = 1 能量，缓存输入免费（复用信号）；usage 缺失保守计 1500。每 Run 幂等结算一次。
- **回充**：子任务完成 +500；独立验证通过 +4000。验收是能量的"食物源"：验证过的成功赚回远超成本的能量。
- **淘汰**：可用能量 < 预留的根停止进入供给；其待认领任务显式结算 `energy_exhausted`。运行中工作正常收尾（已预留）。

## 查询

任务详情附 `energy`（budget/spent/refunded/available）；账本与逐笔流水见 `GET /api/board/tasks/{id}/energy`；每笔过账发 `board.energy_posted` 事件。

## 边界

- 能量是内部选择压力单位，不是货币结算；供应商真实费用对账、跨根团队硬上限尚未提供。
- Demo/测试模型无 usage，按保守价计费——确定性回归同样受选择压力约束。
